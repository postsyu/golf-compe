# ⛳ ゴルフコンペ

ゴルフコンペの「おまけ」（罰ゲーム・ドラコン・ニアピン）をスマホで記録して、公開ダッシュボードでリアルタイムに共有する Web アプリです。スコアや順位の計算は扱いません。

- 画面：GitHub Pages（無料）
- ログインとデータ：Supabase の無料プラン
- サーバーの管理は不要

## できること

| 利用者 | できること |
| --- | --- |
| 一般ユーザー | ログインして参加コンペを選び、ホールごとに罰（池ポチャ・OB・3パット・英語禁止発話・オリジナル罰）を ＋／− で記録、ドラコン・ニアピンの「現在のトップ」を更新 |
| コンペ管理者 | 上記に加えて、一般ユーザーの登録・パスワードリセット、コンペの登録と設定（組分け・対象ホール・オリジナル罰・ローカルルール・状態）、入力ログの閲覧 |
| 全体管理者 | 上記に加えて、コンペ管理者の登録・更新・停止、全コンペの管理 |
| URL を知っている人 | ダッシュボードの閲覧（ログイン不要、開催日の 30 日後まで） |

## 初回セットアップ（1 回だけ）

### 1. Supabase にデータベースを作る

1. Supabase のプロジェクトを開き、左メニューの **SQL Editor** を開きます。
2. このリポジトリの [`supabase/schema.sql`](supabase/schema.sql) の中身をすべて貼り付けて **Run** を押します。
3. 続けて、次の 1 行を自分用に書き換えて実行し、全体管理者（自分）を登録します。

   ```sql
   select app.bootstrap_super_admin('利用者名', '表示名', 'パスワード');
   ```

   - 利用者名は半角英小文字・数字・記号（`_` `.` `-`）で 2〜32 文字です。例：`owner`
   - パスワードは 6 文字以上です。
   - 実行後に SQL Editor の履歴にパスワードが残るのが気になる場合は、あとでアプリの「パスワード変更」で変えてください。

### 2. 接続先を GitHub に登録する

1. Supabase の **Project Settings → API Keys**（または **Data API**）で次の 2 つを確認します。
   - **Project URL**（例：`https://abcdefgh.supabase.co`）
   - **Publishable key**（`sb_publishable_…`）。古いプロジェクトでは **anon public** key（`eyJ…`）
2. GitHub のこのリポジトリで **Settings → Secrets and variables → Actions → Variables** タブを開き、**New repository variable** で次の 2 つを登録します。

   | Name | Value |
   | --- | --- |
   | `VITE_SUPABASE_URL` | Project URL |
   | `VITE_SUPABASE_ANON_KEY` | Publishable key（または anon key） |

   > この 2 つは画面に埋め込まれる公開用の値なので、Variables（公開）で問題ありません。データの守りはデータベース側で行っています。**service_role key（secret key）は絶対に登録・コミットしないでください。**

### 3. GitHub Pages を有効にする

1. **Settings → Pages** を開き、**Source** を **GitHub Actions** にします。
2. **Actions** タブで「Deploy to GitHub Pages」を選び、**Run workflow** を押します（以後は main に push するたびに自動で公開されます）。
3. 数分後に `https://<GitHubユーザー名>.github.io/golf-compe/` で開けます。

## コンペ当日までの流れ

1. 全体管理者でログイン → ☰ →「管理メニュー」→「ユーザー管理」で参加者を登録（初期パスワードを本人に伝える）。
2. 「＋ 新しいコンペ」でコンペを登録 → 組分け・英語禁止ホール・ドラコン／ニアピンのホール・オリジナル罰・ローカルルールを設定して保存。
3. 「ダッシュボードURL」をコピーして LINE などで共有。
4. 当日、状態を「開催中」にする。終わったら「終了」にする（以後は入力不可）。

## 仕組みのメモ

- データベースのテーブルは `app` スキーマにあり、API からは直接読めません。画面は `public.api_*` 関数だけを呼びます。
- パスワードは bcrypt でハッシュ化して保存し、ログイン状態はランダムなトークン（30 日有効）で管理します。10 回続けて失敗すると 15 分ロックします。
- リアルタイム更新は、各画面が 3〜4 秒ごとに「版番号」だけを確認し、変わっていたときだけデータを読み直す方式です。
- ダッシュボードは開催日（日本時間）の 30 日後を過ぎると表示されなくなります。データは削除されません。
- Supabase の無料プランは 1 週間使われないと一時停止します。[`keepalive.yml`](.github/workflows/keepalive.yml) が 3 日おきに軽い問い合わせを送って防ぎます。ただし GitHub は、60 日間更新のない公開リポジトリの定期実行を自動で止めます。止まった場合は Actions タブから再開してください。一時停止しても、Supabase の管理画面の **Resume project** で元に戻せます。
- 画面の文言は [`src/i18n.ts`](src/i18n.ts) にまとめてあり、将来の多言語化に対応できます。

## 開発

```bash
cp .env.example .env.local   # 接続先を書き込む

```
